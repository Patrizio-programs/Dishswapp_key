01 · Design direction

Keep the brand. Change the mobile experience.

A proposed Android-first app shell—not a rebrand and not a shrink-to-fit desktop page.

DishSwapp should feel like a welcoming kitchen companion: easy to explore with one hand, calm to read while cooking, and open to contributions from the community.

Preserve

The DishSwapp character

  • Brand colors: teal, peachy pink, spice, cream, oat, ink, muted, and border.
  • Playfair Display for recipe and editorial headlines.
  • Inter for Android UI, body copy, buttons, and captions.
  • JetBrains Mono for quantities, timers, ratings, and tracked labels.
  • Warm, open, generous language: “Cook,” “swap,” “save,” and “share.”

Propose

Mobile-first structure

  • Replace desktop-style navigation with four clear Android destinations.
  • Put recipe search and cuisine discovery near the top of Home.
  • Give recipe details a focused, sticky “Start cooking” action.
  • Use a distraction-light, one-step-at-a-time cooking mode.
  • Use Android-native back, sheets, touch feedback, and system insets.

Primary mobile journeys

01 · Discover

Browse cuisines, search ingredients, and open a recipe without navigating a desktop menu.

02 · Cook

Check ingredients, adjust servings, and move through clear, timed cooking steps.

03 · Contribute

Save a dish, share an ingredient swap, and credit the cook who tried it.

Platform rules

  • 01Edge-to-edge: respect Android status-bar, gesture, keyboard, and cutout insets.
  • 02Top-level navigation: Home, Search, Cookbook, Profile in a persistent Material 3 navigation bar.
  • 03Deeper screens: use the system Back action; hide the top-level bar in Recipe Detail and Cooking Mode.
  • 04Native surfaces: use bottom sheets for filters, servings, and “Share a swap”; use snackbars for confirmation and Undo.
  • 05Touch: minimum 48 × 48 dp interactive targets, visible press states, and no hover-only actions.
  • 06Theme: seed Material 3 from DishSwapp tokens so dynamic system color does not replace the brand palette.

Playfair Display

Recipe titles and editorial headlines. On mobile, use about 26–30 sp for the main recipe title.

Inter

Controls, navigation, body copy, and buttons. Keep reading text around 16 sp where space allows.

JetBrains Mono

Quantities and timers with tabular figures; use for compact tracked labels, not body paragraphs.

Contrast note. Keep small text off pink and spice surfaces. Reserve the spice CTA for its large, bold action label; use teal with white text for standard-size primary buttons. Verify final color pairs against WCAG AA in the implemented theme.

03 · Recipe detail

What this screen changes

Cooking-first hierarchy

  • Show the dish, title, author, time, and servings before the long method.
  • Keep quantities in JetBrains Mono so the numbers scan quickly.
  • Use checkable ingredient rows with an explicit serving-size control.
  • Preview the first steps, then move into a dedicated cooking mode.

Android action behavior

  • Use native Back to return to the previous screen and preserve the search position.
  • Keep the contextual bottom action above the Android gesture area.
  • Hide the top-level navigation bar here to avoid stacking it with the cooking action.
  • Make Save a separate, 48 dp touch target with a clear saved state.
Spice CTA rule: Use the brand’s #E07A3B for the main “Start cooking” action on this screen only. Pair it with a large, bold ink label; use teal buttons for standard-size actions.

Implementation checklist

  • Use Material 3 components in Compose, themed with the supplied tokens.
  • Bundle or load Playfair Display, Inter, and JetBrains Mono reliably.
  • Use the approved logo asset; mockup wordmarks are text stand-ins.
  • Replace illustrated food blocks with approved contributor photography.
  • Test 360–430 dp phone widths and smaller-screen fallbacks.
  • Test TalkBack labels, font scaling, keyboard overlap, and system Back.
  • Keep text contrast at WCAG AA; don’t place small copy on pink or spice.
  • Apply the brand-book dark neutral tokens when dark mode is supported.
Suggested build order: wire brand tokens and fonts → build the app shell and navigation → create the recipe card and Search → implement Recipe Detail and Cooking Mode → add Cookbook and the contribution bottom sheets → verify Android accessibility and system insets.
