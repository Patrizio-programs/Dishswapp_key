## Context

The Dishswapp Android app is a Capacitor WebView shell that loads the same website as browser visitors, so it currently looks like the mobile website. The user wants an app-only UI variant — bottom tab bar, native-feel polish, and web-only furniture (footer/hamburger nav) hidden — while the website stays pixel-identical. Since the app and site share one codebase, this is done by detecting the app at request time and branching the layout.

A key reuse opportunity: `src/components/Navbar.astro` already contains a designed bottom tab bar (`.mobile-tab-bar`: Home / Search / Cookbook / Profile, safe-area aware) used on mobile web. The app variant reuses that pattern.

## App detection (server-side, no visual flash)

- **`src/middleware.ts`** — wrap `clerkMiddleware()` with `sequence()` (from `astro:middleware`) and a tiny `appMode` handler that sets `Astro.locals.isApp = /;\s*wv\)/.test(request.headers.get('user-agent'))`. Capacitor's Android WebView UA always contains `; wv)`.
- **`src/env.d.ts`** — add `App.Locals { isApp: boolean }` declaration.
- **`src/layouts/Layout.astro`** — `const isApp = Astro.locals.isApp` → `<html class="app-mode" …>` when true, and import the new `src/styles/app.css`.
- No client script needed; SSR renders the right variant on every request.

## Files to change

1. **`src/middleware.ts`** — app-mode detection (above).
2. **`src/env.d.ts`** — `App.Locals` type.
3. **`src/layouts/Layout.astro`** — `app-mode` class on `<html>` + import `../styles/app.css`.
4. **`src/components/Navbar.astro`** — frontmatter reads `Astro.locals.isApp`. Website branch: keep the current markup/styles untouched. App branch renders:
   - **Compact app header** (`app-header`): brand wordmark + right cluster reusing the existing Clerk `<Show signed-out>` login pill / `<Show signed-in>` `<UserButton />`. Hamburger and nav links omitted (covered by tabs).
   - **App tab bar** (`app-tab-bar`): the existing 4 tabs (Home `/`, Search `/recipes/`, Cookbook `/cookbook`, Profile `/dashboard`) plus a **Submit** center tab (`/submit-recipe`, `bi-plus-circle` icon) — matching the approved scope. Current-page highlighting via the existing `current()` helper.
5. **`src/components/Footer.astro`** — render nothing when `Astro.locals.isApp` (template conditional; one file covers every page that includes it).
6. **`src/pages/index.astro`** — app-mode-only link row (About · Donate) near the page bottom so those pages stay reachable in the app (the Footer's own links are `#` stubs today). Website output unchanged.
7. **`src/styles/app.css`** (new) — everything scoped under `html.app-mode`, so the website is unaffected:
   - Tab bar & header styles: always-visible fixed bottom tab bar (5 columns, 48px+ touch targets, safe-area bottom inset), compact teal app header with safe-area top inset; `user-select: none` on chrome only.
   - Native polish: `overscroll-behavior-y: none` (kills pull-to-refresh/rubber-band in the WebView), `-webkit-tap-highlight-color: transparent`, `touch-action: manipulation` (no double-tap zoom), body bottom padding for the tab bar.
   - Safety guard: `html.app-mode footer { display: none }`.

**No Android/Gradle changes** — the shell is untouched, so no APK rebuild is needed; the app picks this up when the website deploys.

## Verification

1. `npm run build` passes.
2. `npm run dev`, then `curl` the homepage twice: with a Capacitor WebView UA → expect `class="app-mode"`, no desktop-navbar markup, `app-tab-bar` present, no `<footer>`; with a normal Chrome UA → expect no `app-mode` and unchanged markup.
3. Browser screenshots at mobile viewport (WebView UA) for the app look, and desktop + mobile (normal UA) to confirm the website is visually identical.
4. After the user deploys (their usual git → Vercel flow): reopen the app on device — tab bar everywhere, no footer/hamburger, spacing under the status bar correct. On Android 15+ devices, if content draws under the status bar (edge-to-edge with targetSdk 36), the contingency is adding `padding-top: env(safe-area-inset-top)` in `app.css`, or an Android theme opt-out — decided after seeing the device.
