01 · Scope

One site, two skins

The Android app is a Capacitor WebView shell that loads the same dishswapp.pgmja.com pages as every browser visitor. "App mode" is a render variant of those pages — nothing about the content, data, or auth changes.

The shell's WebView announces itself in its user agent (; wv)). The site reads that header once per request and renders the page with html.app-mode, which switches on the app skin: a compact teal header, a fixed bottom tab bar, no web footer, and Android-appropriate touch behavior. Every browser — desktop and phone — sees the current website, pixel for pixel.

The app getsWhat never changes
Compact app header (wordmark + account) replacing the hamburger navbarAll pages, routes, and content
Fixed 5-tab bottom bar — Home · Search · Submit · Cookbook · ProfileClerk authentication and Google sign-in flow
Flow screens with a back-arrow app bar and sticky action buttonSupabase data, recipe APIs, admin tools
Footer hidden; About · Donate move onto the Home screenSEO, OG tags, PWA manifest
Native touch: no pull-to-refresh, no tap flash, safe-area spacingWebsite layout at every breakpoint

A note on scope

This spec covers the app-mode skin only. It inherits every token, type rule, and voice decision from DishSwapp Brand Book v2.0 · Nov 2026 — nothing here redefines the brand, it relocates it. Deployment, Clerk flows, and the Play Store listing are out of scope.

03 / 12
03 · Android Alignment

Behave like an Android app

The brand look stays; the platform conventions follow Material. Mockups in this spec are drawn on a 412 × 892 dp Pixel-class frame.

DO

  • 48 dp minimum touch targets on every interactive element; 8 dp rhythm for all spacing (already the brand grid).
  • Edge-to-edge teal top: status bar and app header share #3D717C so the brand owns the top edge; white system icons.
  • Gesture navigation: back gesture pops WebView history; on top-level screens it exits. The system pill floats over the cream strip below the tab bar.
  • State layers, not ripples: pressed elements tint to oat (#EFE5D4) over 200 ms; cards press flat (shadow md → sm).
  • Line icons at 24 dp, 1.5 px stroke — Bootstrap Icons, ink by default, spice reserved for "love" and "spice" moments (Brand Book §12).
  • Fixed labels under tab icons — Material bottom navigation, not an iOS tab bar, not a drawer.

DON'T

  • No pull-to-refresh spinner — the recipe feed is not a mail inbox; overscroll is disabled in app mode.
  • No hamburger drawer in the app — the tab bar covers Dashboard / About / Donate routing (About · Donate live on Home).
  • No iOS patterns: no home indicator, no back chevron "<" (use the Android arrow ←), no bottom sheet grabs.
  • No filled/solid icon variants — the system is line-only.
  • No pure black (#000) anywhere — ink #2C2A28 on cream only.
  • No serif (Playfair) inside buttons, tab labels, or nav — sans (Inter) carries all UI text (Brand Book §08).

Why the fonts don't change

Android apps ship with Roboto by default, but DishSwapp's identity is Playfair + Inter. The WebView already loads both via Google Fonts, and Inter's metrics sit close enough to Roboto that system text (paste sheets, autofill) won't clash. Keep the brand faces.

Back stack rules

Android back on a flow screen pops to the previous top-level screen — never sideways between tabs. Tapping the current tab scrolls to top; tapping it again does nothing. After sign-out (Profile → account menu), the app lands on Home.

Feel is a feature. Each row is a concrete rule with its implementation point.

Android 15 edge-to-edge

The app targets SDK 36, where the system draws content edge-to-edge. The teal header + teal status bar make the top edge seamless by design; if any screen's content still rides under system bars on a test device, add env(safe-area-inset-top) padding in app.css — decided on device, not speculatively.

App tokens (paste into src/styles/app.css)

html.app-mode {
  --app-header-h: 42px;        /* + env(safe-area-inset-top) */
  --app-tabbar-h: 52px;        /* + env(safe-area-inset-bottom) */
  --app-gutter: 12px;          /* 8-pt rhythm: 12 = 1.5 × 8 */
  --app-motion: 200ms;         /* all state transitions */
  --app-touch-min: 48px;       /* Material minimum target */
  --app-bar-blur: rgba(251,247,241,.98);
}

Everything else — colors, radii, shadows, type — reads the existing Brand Book tokens; app.css must not redefine them.
